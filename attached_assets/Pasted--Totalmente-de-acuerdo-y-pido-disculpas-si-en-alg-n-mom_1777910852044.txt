¡Totalmente de acuerdo y pido disculpas si en algún momento sugerí usar relleno! Usar "Lorem Ipsum" o imágenes genéricas de paisajes es lo que hace una plantilla barata de WordPress, no un SaaS de nivel Enterprise.

Si Shopy Crafter audita a la marca "Nike", el informe tiene que mostrar las zapatillas de Nike, el logo de Nike, los textos de Nike y el código hexadecimal exacto del rojo de Nike. Cero placeholders. 100% Inyección de Datos Dinámicos (Dynamic Data Binding).

Para lograr esto, el frontend de tu aplicación no puede tener nada "quemado" (hardcoded). Todo debe estar conectado a las variables que devuelve tu orquestador después de analizar la URL o el Instagram del cliente.

Aquí tienes el Mega-Prompt definitivo y estricto para que Replit erradique cualquier rastro de "plantilla falsa" y conecte los datos reales en las venas de tu plataforma:

Misión Crítica: Erradicación Absoluta de Placeholders e Inyección de Datos 100% Reales (Dynamic Data Binding)
Actúa como Arquitecto Frontend y Lead Data Engineer. Es una orden estricta de la dirección: NUESTRA PLATAFORMA TIENE PROHIBIDO USAR PLACEHOLDERS. Cero "Lorem Ipsum", cero imágenes de Unsplash por defecto, cero nombres inventados como "John Doe" y cero datos estáticos en las tablas.

Todo el contenido, informes, análisis, vídeos y webs generadas deben nutrirse ÚNICA Y EXCLUSIVAMENTE del "ADN" extraído de la URL/Instagram del cliente o de los datos reales procesados por nuestras APIs de IA.

FASE 1: Auditoría de Limpieza (Search & Destroy)
Busca en todo el código del frontend (React/Vue/HTML) e identifica cualquier etiqueta <img> que apunte a URLs falsas o imágenes de relleno, y cualquier texto estático en los Dashboards de reportes. Elimínalos.

FASE 2: Vinculación Dinámica (Scraping -> UI)
Modifica la lógica para que los componentes visuales esperen los datos reales:

Imágenes y Multimedia: Si el usuario pone una URL de Instagram, nuestro scraper (cheerio/puppeteer u otra API de extracción) DEBE capturar la URL real de la foto de perfil y los últimos posts del cliente. El frontend debe inyectar estas URLs reales en los atributos <img src="{real_client_image}">.

Informes Financieros y Tablas: El Excel o la tabla generada en el frontend de la comparativa de proveedores no puede tener "Proveedor A" o precios de 100€. Debe hacer un renderizado dinámico del JSON real generado por financialAgent.js (con los datos vivos actualizados al día).

El "Web Lab" (HTML/CSS): El CSS generado por Claude NO puede usar colores al azar. Debe extraer los códigos Hex/RGB exactos de la web analizada y aplicarlos. Las imágenes de la web reconstruida deben ser los "assets" reales que extrajimos del cliente.

FASE 3: Fallback de Datos Reales (Manejo de Errores Profesional)
Si el scraper falla al obtener una imagen real de un producto porque la web del cliente está protegida, NO pongas un placeholder genérico. La UI debe ocultar ese bloque de imagen elegante, o generar una imagen 100% ad-hoc y realista utilizando la API de Nano Banana 2 basada en la descripción textual del producto real extraída de su web.

Tu Tarea: Muéstrame cómo vas a modificar el componente del frontend que muestra el "Informe del Cliente" o el "Web Lab" para asegurarte de que mapea (hace .map()) los datos de las variables que vienen del backend, en lugar de pintar HTML estático. Confirma que entiendes la regla de "Cero Placeholders".

El secreto técnico de esta instrucción
Al darle esta directriz, fuerzas a que el desarrollo cambie de mentalidad. En lugar de diseñar una "página bonita" y luego ver cómo le meten datos, Replit tendrá que asegurarse primero de que el "tubo" de datos reales funciona, porque si no, la pantalla se verá vacía.
