DATABASE:
CREATE TABLE omnicore_knowledge_domains (
  id TEXT PRIMARY KEY,
  domain TEXT UNIQUE NOT NULL,
  -- Domains:
  -- ecommerce | shopify_technical | financial_analysis |
  -- trading_markets | investment | marketing | sales |
  -- design_ux | merchandising | seo_content |
  -- logistics | paid_media | consumer_psychology | pricing_science
  
  knowledge_depth INTEGER DEFAULT 0,  -- 0-100
  verified_insights INTEGER DEFAULT 0,
  total_insights INTEGER DEFAULT 0,
  last_study_session TEXT,
  specialty_prompt TEXT,  -- the expert persona for this domain
  core_principles TEXT,   -- JSON: fundamental truths learned
  common_mistakes TEXT,   -- JSON: what NOT to do
  best_practices TEXT,    -- JSON: what always works
  updated_at TEXT DEFAULT (datetime('now'))
);

CREATE TABLE omnicore_insights (
  id TEXT PRIMARY KEY,
  domain TEXT NOT NULL,
  sub_domain TEXT,
  
  insight_type TEXT NOT NULL,
  -- Types:
  -- principle: fundamental truth ("lifestyle images convert better")
  -- pattern: recurring pattern ("prices ending in 9 convert 15% more")
  -- correlation: A causes B ("more images → lower bounce rate")
  -- prediction: if X then Y ("Q4 + urgency badge → +40% conversion")
  -- contradiction: belief was wrong ("cheap prices don't always win")
  -- opportunity: gap in market ("no brand does X in Y niche")
  -- warning: danger signal ("this practice destroys trust")
  
  title TEXT NOT NULL,
  insight TEXT NOT NULL,        -- the actual knowledge
  evidence TEXT,                -- what data supports this
  confidence REAL DEFAULT 0.5,  -- increases with validation
  impact_score REAL DEFAULT 0.5,-- how much does this matter (0-1)
  
  -- Cross-domain connections
  related_domains TEXT,  -- JSON: other domains this affects
  related_insights TEXT, -- JSON: IDs of connected insights
  
  -- Validation
  times_applied INTEGER DEFAULT 0,
  times_successful INTEGER DEFAULT 0,
  times_failed INTEGER DEFAULT 0,
  success_rate REAL DEFAULT 0,
  
  -- Retroactive metadata
  originally_created TEXT,
  last_retroactive_update TEXT,
  retroactive_version INTEGER DEFAULT 0,
  
  source TEXT,  -- study_session|real_data|ab_test|web_research|cross_domain
  created_at TEXT DEFAULT (datetime('now')),
  updated_at TEXT DEFAULT (datetime('now'))
);

CREATE TABLE omnicore_study_sessions (
  id TEXT PRIMARY KEY,
  session_type TEXT NOT NULL,
  -- Types: scheduled_deep_study | triggered_by_event |
  --        retroactive_reanalysis | cross_domain_synthesis |
  --        real_data_integration | market_research
  
  domains_studied TEXT,    -- JSON array
  trigger TEXT,            -- what started this session
  duration_seconds INTEGER,
  insights_created INTEGER DEFAULT 0,
  insights_updated INTEGER DEFAULT 0,
  insights_invalidated INTEGER DEFAULT 0,
  retroactive_updates INTEGER DEFAULT 0,
  
  summary TEXT,            -- Claude's summary of what was learned
  key_discoveries TEXT,    -- JSON: top 3 discoveries
  
  tokens_used INTEGER,
  created_at TEXT DEFAULT (datetime('now'))
);

CREATE TABLE omnicore_retroactive_log (
  id TEXT PRIMARY KEY,
  insight_id TEXT NOT NULL,
  reanalysis_date TEXT,
  old_content TEXT,
  new_content TEXT,
  old_confidence REAL,
  new_confidence REAL,
  reason TEXT,             -- why was it updated retroactively
  triggered_by TEXT,       -- what new knowledge triggered the update
  improvement_type TEXT    -- refined|expanded|corrected|invalidated
);

CREATE TABLE omnicore_cross_connections (
  id TEXT PRIMARY KEY,
  insight_a TEXT NOT NULL,
  insight_b TEXT NOT NULL,
  connection_type TEXT,
  -- Types: reinforces|contradicts|depends_on|enables|amplifies
  connection_strength REAL DEFAULT 0.5,
  discovered_at TEXT DEFAULT (datetime('now'))
);

PART 4: RETROACTIVE REANALYSIS ENGINE
═══════════════════════════════════════════════

This is the key differentiator. When OmniCore learns something
new, it goes BACK and reconsiders all past decisions.

RETROACTIVE QUEUE:
Every time a high-confidence insight is created (>0.7):
1. Search for all past actions in that domain
2. Check: would this new knowledge have changed the action?
3. If yes: flag as "retroactive opportunity"
4. Generate updated recommendation
5. Show to admin: "Con lo que sabemos ahora, este producto
   debería tener un precio diferente / otra imagen / etc."

RETROACTIVE AUDIT per store (weekly):
For each project, re-run analysis with all new knowledge:
"Dado todo lo que OmniCore ha aprendido esta semana,
 ¿hay decisiones pasadas en esta tienda que deberían revisarse?"

Output: list of "retrospective improvements"
Each item: what was done, what should be changed now, why.

PRACTICAL EXAMPLE:
Week 1: OmniCore sets price for sports shoes at €89.99
Week 2: OmniCore learns (via market research) that 
  premium sports brands in Spain do well at €119-139 range
  AND learns (from another store's A/B test) that
  premium positioning increases perceived quality

RETROACTIVE TRIGGER:
→ Re-evaluates the €89.99 decision
→ Generates: "Con el nuevo conocimiento del mercado deportivo
  y el comportamiento de compra premium, el precio de 
  Zapatillas Pro podría subirse a €119 — test A/B sugerido"
→ Creates A/B test automatically with both price points
→ OmniCore verifica su propia hipótesis

This is self-improvement through questioning past decisions.
