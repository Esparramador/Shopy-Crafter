## BUG #8 🟠 — Stale closure en `setInterval` polling de Audit Tienda

**Fichero**: `pages/projects/Audit.tsx runStoreAudit()`

**Problema**: 
```js
const poll = setInterval(async () => {
  await fetchStoreAuditResults();
  if (storeAuditResults || attempts >= 16) {  // ⚠ stale closure
    clearInterval(poll);
  }
}, 15000);
```

`storeAuditResults` se lee del closure inicial (siempre `null`). El polling **nunca terminaba** aunque hubiera resultados → memoria fugada + warnings infinitos en consola.

**Fix aplicado**: leer `storeAuditResults` directamente del fetch dentro del interval, no del state:

```js
const r = await fetch(`...audit/results`, { credentials: "include" });
if (r.ok) {
  const d = await r.json();
  if (d && (d.scores || d.summary || d.recommendations)) {
    setStoreAuditResults(d);
    clearInterval(poll);  // ← termina correctamente
  }
}
```

## BUG #17 🔴 — Files >35MB no caben en `content` base64

**Fichero**: `routes/fs-pro.ts` (todos los endpoints que persisten archivos)

**Problema**: 
- Express body limit = 50MB (incluye base64 con +33% overhead)
- Un MP4 de 10s a 1080p suele pesar 15-25MB → como base64: 20-33MB (cabe pero peligroso)
- Compose con voz + música + video: salida puede pasar 30MB → base64 >40MB → riesgo de bloqueo
- Música de 47s puede pesar 8-15MB

**Fix aplicado**: helper `saveToVaultSmart()` que decide:
- Si `buffer.length > 2MB` → upload a Object Storage (`objectPath`), guarda solo metadata en DB
- Si `≤ 2MB` → almacena como `content` base64 (típico para imágenes pequeñas, TTS corto, SFX)

**Endpoints migrados**: generate-image, edit-image, remove-bg, replace-bg, upscale, generate-video, tts, sfx, music, compose. **10 endpoints en total**.

**Beneficio adicional**: el endpoint `/preview` del vault automáticamente sirve desde Object Storage cuando hay `objectPath`, así que descargar/visualizar files grandes desde la UI sigue funcionando sin tocar nada.

### BUG #20 🔴 — `routes/exports.ts` 24 endpoints SIN AUTH (data leak crítico)

**Fichero**: `routes/exports.ts` + `routes/index.ts` (montaje)

**Problema crítico de seguridad**: TODOS los 24 endpoints `/api/projects/:projectId/exports/*` están **sin middleware de auth**:
- `/exports/financial` → revenue, márgenes, COGS de cualquier cliente
- `/exports/revenue` → ingresos por mes
- `/exports/ab-tests` → resultados estratégicos
- `/exports/product-catalog` → catálogo completo
- `/exports/xlsx/full` → todo el dataset del proyecto
- `/exports/zip/all` → backup completo

Cualquier persona con la URL podía descargar reportes financieros de cualquier proyecto. Como la URL incluye `:projectId` numérico, basta probar `1, 2, 3...` para enumerar.

Los handlers tampoco verifican `req.session` internamente.

**Fix aplicado**: en `routes/index.ts`, añadido middleware `requireProjectAccess` aplicado al prefijo `/projects/:projectId/exports`:

```ts
router.use("/projects/:projectId/exports", requireAuth, requireProjectAccess);
router.use(exportsRouter);
```

Los endpoints públicos `/exports/brand-css/:projectId`, `/exports/brand-kit/:projectId`, `/exports/brand-guide/:projectId`, `/exports/report-css/:projectId/:area` **NO se ven afectados** porque su path empieza con `/exports/` (sin `/projects/`), no por `/projects/:projectId/exports/`. Eso es intencional: la tienda Shopify carga el CSS de marca desde el storefront sin login.

### BUG #21 🔴 — `requireClientAccess` original era buggy (clientId vs projectId)

**Fichero**: `lib/auth.ts`

**Problema**: La función `requireClientAccess` original comparaba:
```ts
if (req.session.clientId === projectId) { next(); return; }
```

`session.clientId` es un UUID de usuario (`"abc-123-def"`), `projectId` es un número (`"42"`). NUNCA coincidirían → cualquier client siempre obtenía 403 → por eso en el primer turno la borré, dejando los exports sin protección (causa del Bug #20).

**Fix aplicado**: nueva `requireProjectAccess` async que hace lookup real en DB:
```ts
const [project] = await db.select({ clientId: projectsTable.clientId })
  .from(projectsTable)
  .where(eq(projectsTable.id, projectId)).limit(1);
if (project.clientId !== req.session.clientId) {
  res.status(403).json({ error: "Access denied" });
  return;
}
```

Admin role siempre allowed. Async porque hace query DB — ligero overhead pero correcto.

**Problema**: Si el usuario no ejecuta `pnpm add web-push` antes de arrancar, el server falla con "Cannot find module 'web-push'".

**Decisión**: trade-off aceptado. Hacer lazy import requeriría refactorear todo el archivo (el tipo `webpush.PushSubscription` se usa en firmas). El requisito está documentado en `09-APPLY-GUIDE.md` y `11-FUSION-STUDIO-PRO.md`.
