TAREA 1.1 — AUDITORÍA AUTOMATIZADA
═══════════════════════════════════════════════════════════════════

Crea un script en /scripts/audit-buttons.ts que:

1. Recorra recursivamente /client/src/ buscando todo elemento con role="button",
   <button>, <Button>, onClick handlers, o componentes tipo *Button.

2. Para cada botón detectado, extraiga:
   - Archivo y línea
   - Sección (deducida del path: /pricing/, /seo/, /audit/, etc.)
   - Texto visible del botón
   - Tiene onClick handler? (sí/no)
   - El handler llama a una función real o es vacío/console.log?
   - El handler hace fetch/axios a algún endpoint? Cuál?
   - Tiene estado de loading?
   - Tiene manejo de error?

3. Genere un reporte en /docs/buttons-audit.md con esta tabla por sección:

   | Sección | Botón | Archivo:línea | Endpoint | Loading | Error | Estado |
   |---------|-------|---------------|----------|---------|-------|--------|
   | Pricing | Optimizar | Pricing.tsx:147 | /api/pricing/optimize | ❌ | ❌ | 🔴 ROTO |
   | SEO | Analizar | SeoEngine.tsx:89 | /api/seo/analyze | ✅ | ✅ | 🟢 OK |

   Estados:
   🟢 OK = funcional + tiene loading + tiene error handling
   🟡 PARCIAL = funcional pero falta loading o error UI
   🔴 ROTO = onClick vacío, console.log, o no hace nada real
   ⚫ DESCONOCIDO = no se puede determinar automáticamente

4. Al final del reporte, añade resumen:
   - Total botones encontrados: N
   - Por estado: X verdes, Y amarillos, Z rojos
   - Por sección: ranking de secciones con más botones rotos
   - Endpoints únicos detectados
   - Endpoints referenciados que NO existen en /server/routes/

EJECUTA ESTE SCRIPT Y MUÉSTRAME EL REPORTE COMPLETO antes de continuar.

TAREA 1.2 — COMPONENTE <ActionButton> UNIFICADO
═══════════════════════════════════════════════════════════════════

Crea /client/src/components/ui/ActionButton.tsx con esta API:

  <ActionButton
    variant="primary" | "secondary" | "ghost" | "danger" | "ai"
    size="sm" | "md" | "lg"
    icon={<IconLucide />}                    // opcional
    loadingText="Optimizando..."              // texto en loading
    successText="Optimizado"                  // texto tras éxito (1.5s)
    confirmMessage="¿Aplicar a 87 productos?" // si requiere confirmación
    estimatedCost={0.42}                      // si tiene coste IA en €
    onAction={async () => { ... }}            // handler async obligatorio
    disabled={...}
    tooltip="..."
  >
    Optimizar
  </ActionButton>

ESTADOS QUE DEBE MANEJAR INTERNAMENTE:

  • idle      → render normal
  • confirming → modal de confirmación (si confirmMessage existe)
  • loading   → spinner inline + loadingText, disabled, opacity 0.85
  • success   → check verde 1.5s + successText, luego vuelve a idle
  • error     → cruz roja 1.5s + toast con error.message + botón "Reintentar"

VARIANTES VISUALES (dark theme, mantén la estética actual):

  primary   → bg teal #14b8a6, text dark
  secondary → border #334155, text #cbd5e1, hover bg #1e293b
  ghost     → solo text, sin border
  danger    → bg red, text white
  ai        → border violeta + icono spark, gradient sutil teal→violeta

REQUISITOS TÉCNICOS:

  - Usa el sistema de toasts existente (sonner, react-hot-toast, lo que tengas)
  - Si onAction lanza error, captúralo, muestra toast con .message del error,
    pero NO crashees el componente
  - Loading state se activa AUTOMÁTICAMENTE al ejecutar onAction
  - Si onAction tarda >5s, muestra texto adicional "Tomando más de lo esperado..."
  - estimatedCost se muestra en el modal de confirmación: 
    "Coste estimado: €0.42 en créditos IA"
  - Accesible: aria-busy durante loading, aria-disabled cuando aplique
