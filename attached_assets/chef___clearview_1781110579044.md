# ClearView Design System

## Overview

ClearView is an accessibility-first design system built to meet WCAG AAA standards throughout. Engineered for government portals, public service applications, and any product where universal access is non-negotiable, it prioritizes maximum contrast, large touch targets, screen-reader optimization, and crystal-clear visual hierarchy. Every decision -- from the 7:1 minimum contrast ratio to the 48px touch targets -- serves the mandate that no user is left behind.

---

## Colors

- **Blue** (#0052CC): Primary actions, links
- **Green** (#006644): Success, confirmed
- **Red** (#BF2600): Error, destructive
- **Surface Base** (#FFFFFF): App background
- **Surface Highlight** (#DEEBFF): Selected rows, active areas
- **Success** (#006644): Confirmed, valid
- **Warning** (#974F0C): Warning, needs attention
- **Error** (#BF2600): Error, invalid, destructive
- **Info** (#0052CC): Informational

## Typography

- **Headline Font**: Lexend
- **Body Font**: Open Sans
- **Mono Font**: Fira Code

Lexend is specifically designed to improve reading proficiency by reducing visual stress.

- **h1**: Lexend 36px bold, 1.25 line height
- **h2**: Lexend 28px semibold, 1.3 line height
- **h3**: Lexend 22px semibold, 1.35 line height
- **h4**: Lexend 18px medium, 1.4 line height
- **body**: Open Sans 16px regular, 1.7 line height
- **small**: Open Sans 14px regular, 1.6 line height
- **tiny**: Open Sans 13px regular, 1.5 line height
- **mono**: Fira Code 15px regular, 1.6 line height

Minimum body text: 16px. No text in the interface may be smaller than 13px.

## Border Radius

- **radius-sm** (4px): Chips, badges
- **radius-md** (8px): Cards, inputs, buttons
- **radius-lg** (12px): Modals
- **radius-pill** (9999px): Tags

## Elevation

ClearView uses flat design with strong borders for clarity. Shadows are minimal and supplementary, never the primary means of communicating elevation.
- **shadow-sm**: 1px offset, 3px blur, #091E42 at 8%. Subtle lift.
- **shadow-md**: 4px offset, 8px blur, #091E42 at 12%. Cards.
- **shadow-lg**: 8px offset, 16px blur, #091E42 at 15%. Modals.
All elevated elements must also have a visible border for users who cannot perceive shadows.

## Accessibility Patterns

- **Skip Links:** Every page includes a "Skip to main content" link as the first focusable element.
- **Focus Visible:** All interactive elements show a 3px blue outline on `:focus-visible`. Never remove outline.
- **ARIA Landmarks:** Use ``, ``, ``, ``, `` with explicit `role` attributes where needed.
- **Live Regions:** Dynamic content updates (toasts, errors) use `aria-live="polite"` or `aria-live="assertive"`.
- **Error Handling:** Errors are announced, visually marked with icon + color + text, and linked via `aria-describedby`.
- **Motion:** All animations respect `prefers-reduced-motion: reduce`. Critical information never depends on animation.

---

## Do's and Don'ts

1. **Do** maintain a minimum 7:1 contrast ratio for all text; this is AAA, not AA.
2. **Don't** rely on color alone to convey meaning -- always pair color with text, icons, or patterns.
3. **Do** ensure every interactive element has a minimum 48px x 48px touch target.
4. **Don't** remove or hide focus indicators; the 3px blue outline is mandatory on all focusable elements.
5. **Do** associate every form input with a visible `` using `for`/`id` pairing.
6. **Don't** use placeholder text as a substitute for labels; placeholders disappear on input.
7. **Do** include skip links, ARIA landmarks, and live regions on every page.
8. **Do** test with screen readers (NVDA, VoiceOver, JAWS) as part of the development process.
9. **Don't** use font sizes below 13px anywhere in the interface.
10. **Do** provide `prefers-reduced-motion` alternatives for all transitions and animations.
