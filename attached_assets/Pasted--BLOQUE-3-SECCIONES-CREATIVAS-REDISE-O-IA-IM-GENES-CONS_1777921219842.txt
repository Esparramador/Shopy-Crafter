TAREA 4.1 — REFACTOR SECCIONES RESTANTES
═══════════════════════════════════════════════════════════════════

Aplica el mismo patrón <ActionButton> + useAIAction a todas las secciones 
que queden. Para cada una:

1. Lee /docs/buttons-audit.md (del Bloque 1) y trata todos los botones 
   marcados como 🔴 ROTO o 🟡 PARCIAL
2. Identifica el endpoint que debe llamar (verifica que existe)
3. Aplica el patrón estándar
4. Documenta en /docs/section-refactor-{nombre}.md

Si encuentras una sección con botones puramente decorativos o sin lógica
clara, MUÉSTRAMELOS antes de tocar para que decida si eliminarlos o 
darles funcionalidad.

═══════════════════════════════════════════════════════════════════
TAREA 4.2 — DASHBOARD GLOBAL DE ACCIONES IA
═══════════════════════════════════════════════════════════════════

Crea /client/src/pages/AIActions.tsx — un panel central que muestre:

  • Acciones IA en curso (con su progreso real, cancelables)
  • Historial de últimas 50 acciones (success/error/cancelled)
  • Coste IA acumulado del mes (suma de todos los estimatedCost reales)
  • Top acciones más usadas
  • Alertas: "5 acciones fallaron en la última hora"

Backend: tabla ai_actions_log con columnas:
  id, shop_id, user_id, action_type, endpoint, status, 
  cost_estimated, cost_real, started_at, completed_at, error_message,
  payload (jsonb), result_summary (jsonb)

Cada llamada via useAIAction debe loggear automáticamente aquí.

📋 CÓMO USAR ESTOS 4 BLOQUES
Orden estricto:

Pega Bloque 1 → espera a que el Agent te muestre el reporte de auditoría → revísalo
Solo cuando apruebes el reporte y el <ActionButton> funcione, pega Bloque 2
Tras validar Pricing/Auditoría/SEO/A/B Testing, pega Bloque 3
Cuando termine creativas, pega Bloque 4 para cerrar

Antes de pegar cada bloque, dile al Agent:

"Vas a recibir el bloque N de 4. Confirma que el bloque anterior está completo y pasados los tests antes de empezar"

Si el Agent intenta saltarse pasos (típico cuando tiene prisa):

"STOP. No has completado la tarea X.Y del bloque anterior. Vuelve atrás y termínala antes de continuar"

Si en mitad de un bloque encuentra algo raro en tu código:

"Si algo del código actual no encaja con el plan, NO lo borres. Documéntalo en /docs/incompatibilities.md y dime qué encontraste antes de tocarlo"
