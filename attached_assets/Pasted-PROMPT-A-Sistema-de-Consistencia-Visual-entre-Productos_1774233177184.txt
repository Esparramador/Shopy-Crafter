PROMPT A — Sistema de Consistencia Visual entre Productos
Add Visual Consistency Engine to the platform:

CONCEPT:
Every store needs a unified visual identity across all product images.
This module ensures all generated images feel like they belong to the same brand,
not like random AI outputs. It defines, enforces and repairs visual consistency.

─────────────────────────────────────────
PART 1: BRAND VISUAL DNA EXTRACTOR
─────────────────────────────────────────
On first store scan, Claude analyzes existing product images and extracts:

POST /api/extract-visual-dna
- Download first 6 product images from Shopify
- Send to Claude with vision: 
  "Analyze these product images from a Shopify store. Extract:
   1. Dominant background style (white studio / lifestyle / dark / natural)
   2. Lighting style (hard/soft/natural/studio)
   3. Color temperature (warm/cool/neutral)
   4. Composition style (centered/dynamic/flatlay/3quarter)
   5. Mood/atmosphere (luxury/playful/minimal/editorial/urban)
   6. Recurring props or surfaces (wood, marble, concrete, fabric)
   7. Human presence (never/hands only/full model/lifestyle)
   Return as JSON: { backgroundStyle, lightingStyle, colorTemp, composition, mood, props[], humanPresence, consistencyScore 0-100 }"

Store the extracted DNA as project-level config: /projects/{id}/visual-dna.json

─────────────────────────────────────────
PART 2: CONSISTENCY SCORE PER PRODUCT
─────────────────────────────────────────
For each product image audit:
- Compare product's images against store's Visual DNA
- Claude scores each image 0-100 on: background match, lighting match, mood match
- Flag inconsistencies: "Este producto tiene fondo negro pero tu tienda usa fondo blanco"
- Show per-product consistency badge: Consistent ✓ / Off-brand ⚠ / Inconsistent ✗

Visual Consistency Dashboard:
- Store-wide consistency score (0-100)
- Grid showing all products color-coded by consistency
- "Productos off-brand" list with one-click fix
- Before/after preview of consistency fix

─────────────────────────────────────────
PART 3: STYLE LOCK SYSTEM
─────────────────────────────────────────
Create a StyleLock config per store that all image prompts inherit:

const STYLE_LOCK = {
  backgroundRule: "pure white seamless background OR [extracted lifestyle setting]",
  lightingRule: "soft box lighting, minimal shadows, professional studio",
  colorTempRule: "neutral to slightly warm, 5500K",
  compositionRule: "centered product, 20% padding all sides, portrait 4:5 ratio",
  moodRule: "clean, premium, aspirational",
  propsRule: "minimal props, brand-consistent surfaces only",
  negativeAddons: "busy backgrounds, harsh shadows, cluttered props, inconsistent lighting",
  brandColors: ["#hex1", "#hex2"],  // extracted from logo/existing images
  referenceImageUrl: ""  // optional: user can upload a reference image
}

Every image generation prompt gets appended:
"STYLE CONSISTENCY REQUIRED: ${JSON.stringify(STYLE_LOCK)} — 
All images must feel like they belong to the same professional catalog shoot."

─────────────────────────────────────────
PART 4: CONSISTENCY REPAIR TOOL
─────────────────────────────────────────
"Reparar Consistencia" button:
1. Identifies all off-brand products
2. Generates new Hero image for each with StyleLock enforced
3. Shows side-by-side: current image vs new consistent image
4. User approves/rejects each before uploading
5. Bulk approve: "Aplicar todo" replaces all inconsistent heroes

REFERENCE IMAGE UPLOAD:
- User can upload 1-3 reference photos that define the desired style
- Claude extracts StyleLock from those references automatically
- All future generations match that reference style
- Prompt injection: "Match the exact visual style of this reference: [image_url]. 
  Same lighting, same background feel, same composition energy."

UI: Collection → Set Style editor

"Cómo se verá mi tienda" panel:

PROMPT B — A/B Testing Automático de Imágenes + Métricas Shopify
Add Automated A/B Image Testing Engine connected to Shopify Analytics:

CONCEPT:
Automatically test which image performs better (more clicks, more conversions),
rotate winners, kill losers, and compound improvements over time.
This is the engine that turns image generation into measurable revenue growth.

─────────────────────────────────────────
PART 1: A/B TEST INFRASTRUCTURE
─────────────────────────────────────────
Data model per test (stored in /projects/{id}/ab-tests.json):
{
  testId: uuid,
  productId: string,
  imageType: "hero|lifestyle|ugc|...",
  variantA: { imageUrl, shopifyImageId, prompt, model, generatedAt },
  variantB: { imageUrl, shopifyImageId, prompt, model, generatedAt },
  startDate: ISO,
  endDate: ISO,
  status: "running|paused|completed|winner_declared",
  targetMetric: "ctr|conversion|revenue",
  minimumSampleSize: 100,
  winner: null | "A" | "B",
  confidence: 0-100
}

A/B TEST MECHANICS:
- Shopify doesn't natively support image A/B testing
- Implement via Shopify Script / theme modification:
  Generate a snippet for the store's theme that rotates images based on 
  visitor session ID hash (ensures same visitor always sees same variant):
  
  {% assign visitor_hash = customer.id | default: cart.token | modulo: 2 %}
  {% if visitor_hash == 0 %}
    {% assign hero_image = product.metafields.abtests.variant_a_url %}
  {% else %}
    {% assign hero_image = product.metafields.abtests.variant_b_url %}
  {% endif %}

Store variant assignment in Shopify metafields:
- namespace: "abtests"
- key: "variant_a_url", "variant_b_url", "active_test_id"
- Update via Metafields API

─────────────────────────────────────────
PART 2: METRICS COLLECTION
─────────────────────────────────────────
Since Shopify Analytics doesn't expose per-image data,
collect signals via multiple sources:

SOURCE 1 — Shopify Orders API:
Poll every 6 hours:
GET /admin/api/2024-01/orders.json?created_at_min={testStartDate}
- Track orders containing test products
- Correlate with variant assignment via order timeline + session
- Calculate: conversion rate per variant

SOURCE 2 — Shopify Analytics API:
GET /admin/api/2024-01/reports.json (if Shopify Plus) 
OR use /admin/api/2024-01/customers.json for repeat purchase signals

SOURCE 3 — Custom pixel (inject via ScriptTag API):
POST /admin/api/2024-01/script_tags.json
{
  "script_tag": {
    "event": "onload",
    "src": "https://your-app-domain.com/tracker.js"
  }
}

tracker.js collects:
- Product page views with variant shown
- Add to cart events
- Time on product page
- Image scroll/zoom interactions
- Sends to your app's POST /api/track endpoint

METRICS TRACKED:
- CTR improvement: (variant B clicks / variant A clicks) - 1
- Conversion lift: orders variant B / orders variant A
- Revenue per visitor: (revenue × conversion) / visitors
- Engagement: time on page, scroll depth, zoom events
- Statistical significance: use z-test for proportions

─────────────────────────────────────────
PART 3: STATISTICAL ENGINE
─────────────────────────────────────────
Implement proper statistical significance:

function calculateSignificance(variantA, variantB) {
  // Z-test for two proportions
  const pA = variantA.conversions / variantA.visitors;
  const pB = variantB.conversions / variantB.visitors;
  const pPool = (variantA.conversions + variantB.conversions) / 
                (variantA.visitors + variantB.visitors);
  const se = Math.sqrt(pPool * (1 - pPool) * 
             (1/variantA.visitors + 1/variantB.visitors));
  const z = Math.abs(pA - pB) / se;
  // Convert z to confidence %
  const confidence = (1 - 2 * (1 - normalCDF(z))) * 100;
  return { confidence, winner: pB > pA ? 'B' : 'A', lift: ((pB - pA) / pA) * 100 };
}

AUTO-DECLARE WINNER when:
- confidence >= 95% AND
- minimum sample size reached (default 100 visitors per variant) AND
- test running >= 7 days (avoid day-of-week bias)

On winner declared:
1. Set winning image as Shopify product's position-1 image
2. Archive loser image (don't delete, keep for records)
3. Notify user: "Variante B ganó con 94% de confianza. +23% conversión. Aplicada automáticamente."
4. Auto-generate next challenger: immediately create Variant C to test against the winner
5. Continuous improvement loop: winner always becomes the new control

Claude decides WHAT to test based on hypotheses:

const AB_HYPOTHESES = [
  { 
    name: "Background Impact",

    variantB_instruction: "lifestyle contextual background, aspirational setting",

  {
    name: "Human Presence",

  },
  {
    name: "Angle & Composition", 
    variantA_instruction: "front-facing centered product shot",
    variantB_instruction: "dynamic 3/4 angle with slight rotation, more depth",
    hypothesis: "3D perspective shows product better than flat front"
  },
  {
    name: "Color Temperature",
    variantA_instruction: "cool neutral lighting, clinical clean",
    variantB_instruction: "warm golden hour lighting, inviting atmosphere",
    hypothesis: "Warm lighting creates higher emotional engagement"
  },
  {
    name: "Prop Complexity",
    variantA_instruction: "product alone, zero props",
    variantB_instruction: "product with 2-3 complementary lifestyle props",
    hypothesis: "Styled props increase perceived value"
  },
  {
    name: "UGC vs Studio",
    variantA_instruction: "professional studio quality, perfect lighting",
    variantB_instruction: "authentic UGC style, real person, candid feel",
    hypothesis: "UGC authenticity builds more trust than polish"
  }
]

Claude selects the most relevant hypothesis for each product based on:
- Product category (apparel → test human presence; electronics → test background)
- Current image performance (low CTR → test composition; low conversion → test trust/UGC)
- Store niche (luxury → test prop complexity; streetwear → test UGC vs studio)
- What hasn't been tested yet for this product
