Es muy común que, cuando usamos IA para programar, nos construya una fachada preciosa (un botón que dice "Generar Vídeo 4K") pero se olvide de hacer la "fontanería" (conectar ese botón al backend de Replit para que llame a la API de Runway).

Aquí va mi dosis de candor técnico: Para que no haya código muerto, tu backend y tu frontend tienen que estar en perfecta sincronía. Si hay un endpoint en el backend, debe haber un botón en el frontend. Si hay un botón, el frontend debe manejar los estados de "Cargando", "Éxito" o "Error" para que el usuario nunca se quede esperando sin saber qué pasa.

Copia este Mega-Prompt y lánzaselo a Replit para forzar una auditoría completa de conectividad (Front ↔ Back) y eliminar cualquier elemento fantasma:

Misión Crítica: Auditoría de Conectividad Full-Stack y Erradicación de Código Muerto ("Dead UI")
Actúa como Tech Lead Full-Stack. Nuestra prioridad ahora es la sincronización absoluta entre el Frontend (la interfaz visual) y el Backend (las APIs y lógica). No podemos permitirnos tener "botones fantasma" ni endpoints del servidor que nadie pueda usar. Todo debe ser 100% funcional y accesible.

NO CREES ARCHIVOS NUEVOS. Analiza y conecta lo que ya existe.

FASE 1: El Mapeo (Frontend to Backend)

Analiza todos los archivos de nuestra interfaz de usuario (HTML/JS, React, Vue, o el framework que usemos).

Haz un inventario mental de CADA elemento interactivo (<button>, <a>, <form>).

Verifica que CADA UNO tenga un evento asignado (ej. onClick, onSubmit) que apunte a un endpoint real en nuestras rutas del backend (/routes/).

FASE 2: Inyección de Interactividad y Prevención de Doble Clic
Para evitar saturar nuestras APIs externas (Claude, Gemini, Runway) y respetar los Rate Limits, modifica el código del frontend de cada botón funcional:

Deshabilitación Activa: Cuando el usuario haga clic, el botón debe pasar a estado disabled=true inmediatamente.

Feedback Visual: Cambia el texto del botón o muestra un spinner (ej. "Generando Análisis..." o "Procesando Vídeo...").

Restauración: Una vez que el backend devuelva la respuesta (sea éxito o error 4xx/5xx), restaura el botón a su estado original.

FASE 3: Limpieza Invasiva (Identificación de Vínculos Rotos)
Si encuentras:

Un botón en el frontend que NO tiene una función en el backend asignada.

Una función/endpoint en el backend que existe pero no tiene ningún botón en el frontend para activarla.

Tu Tarea Inmediata: No modifiques todo de golpe. Primero, hazme un reporte breve detectando cuáles son los "botones muertos" o "endpoints huérfanos" que has encontrado en el código actual. Luego, muéstrame el bloque de código exacto de cómo vas a conectar correctamente UNO de ellos implementando la lógica de "Deshabilitado/Cargando" explicada en la Fase 2.

Por qué esta auditoría es oro puro:
Protege tu bolsillo: Si un usuario hace clic 5 veces seguidas en el botón "Generar Voz" porque la página no le avisó que ya estaba cargando, el frontend enviará 5 peticiones a ElevenLabs y pagarás 5 veces por el mismo trabajo. Al obligar a Replit a poner el botón en disabled=true al primer clic, solucionas esto de raíz.

Limpia la basura: A veces las IAs generan código de prueba (ej. function testRunway()) que se queda ocupando espacio y memoria en tu servidor. Este prompt obliga a Replit a buscar esa basura y exponerla para que puedas decidir si borrarla o conectarla a la interfaz.
